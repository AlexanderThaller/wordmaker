= 039: Public site sends no security headers
:severity: Low
:area: Site
:status: fixed
:found: 2026-10-24

[horizontal]
Severity:: Low
Area:: Site
Status:: Fixed

== Summary

Public pages have no `X-Frame-Options`/`frame-ancestors`,
`Referrer-Policy` or `X-Content-Type-Options`. Only the OAuth pages set a
CSP.

== Location

* `src/app.rs`
* `src/site.rs`

== Impact

Pages can be framed for clickjacking, full URLs leak in referrers, and
browsers may sniff content types (see
link:005-media-active-content-site-origin.adoc[issue 5]).

== Suggested fix

* Add `X-Content-Type-Options: nosniff`, `Referrer-Policy:
  strict-origin-when-cross-origin` and `frame-ancestors 'self'` to all
  responses.

== Resolution

`app::router` adds `X-Content-Type-Options: nosniff`, `Referrer-Policy:
strict-origin-when-cross-origin`, `X-Frame-Options: SAMEORIGIN` and
`Content-Security-Policy: frame-ancestors 'self'` to every response that
does not set them itself. The OAuth pages keep their stricter
`frame-ancestors 'none'` policy, and media files their sandbox policy
(link:005-media-active-content-site-origin.adoc[issue 5]).

Framing stays possible from the site itself. The admin interface does not
frame the public site: it renders previews from its own origin into an
`srcdoc` iframe and fetches `/_wm` and `/media` through its proxy, so it
is unaffected.
