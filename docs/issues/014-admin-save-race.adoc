= 014: Switching pages during a save can write one page's content into another
:severity: Medium
:area: wordmaker-admin UI
:status: fixed
:found: 2026-10-24

[horizontal]
Severity:: Medium
Area:: wordmaker-admin UI
Status:: Fixed

== Summary

`save()` does not remember which page it started on. After its awaits it
calls `show(A)` and restores the typed title, even if the user has since
navigated elsewhere.

== Location

* `crates/wordmaker-admin/assets/app.js:492-526`
* `crates/wordmaker-admin/assets/app.js:199-212`

== Impact

. Edit page A and press Save. While it is in flight, navigate to page B
  and confirm "Discard changes?".
. `openPage(B)` returns first. Then `save()` runs `show(A)`: `state.current`
  becomes A, the slug field shows A, the title is reset to the typed value
  (now B's) and the editor still holds B's body.
. The hash says B and the form is dirty. The next Ctrl+S saves B's title and
  body as page A; A's content is lost.

Related: `state.saving` is never checked, so a double Ctrl+S or Save then
Publish sends the same PATCH twice. After a slug rename the second goes to
the old slug, gets a 404 and aborts the publish; duplicate draft PUTs create
extra revisions. `show(page)` also overwrites slug, nav and order edits typed
during the save.

== Suggested fix

* Capture `const target = state.current` at the start of `save()`; after
  each await, stop if `state.current !== target` (or update only
  `state.current` without touching the fields).
* Return early when `state.saving` is set, and disable Save/Publish while
  saving.

== Resolution

* `save()` remembers the page it started on. If another page is open once
  the server has answered (`stillOpen` compares page ids), it leaves the
  form alone, refreshes the page list, reports the save and returns
  `false`, so a Publish that was waiting on it stops too.
* A save while one is under way returns at once, and Save and Publish are
  disabled while saving, so the same PATCH or draft PUT is not sent twice.
* After a save the slug, navigation and order fields keep what was typed
  meanwhile, as the title already did.
* Publish, Unpublish, Discard draft and Delete likewise touch the form only
  if their page is still open when the server answers.
