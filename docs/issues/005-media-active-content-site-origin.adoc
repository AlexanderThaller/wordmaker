= 005: Uploaded HTML/SVG and theme SVGs are served inline on the site origin
:severity: Medium
:area: Media / themes
:status: fixed
:found: 2026-10-24

[horizontal]
Severity:: Medium
Area:: Media / themes
Status:: Fixed

== Summary

`sanitize_filename` keeps any extension, and `/media` is served by
`ServeDir`, which picks the content type from the extension. The content
type stored at upload is never used. Theme assets allow `svg`. Neither
response has `nosniff`, a CSP or `Content-Disposition`.

== Location

* `src/domain/media.rs:229`
* `src/domain/media.rs:294-312`
* `src/site.rs:67-69`
* `src/site.rs:80-89`
* `src/site.rs:576-612`

== Impact

. A prompt-injected MCP or OAuth client uploads `x.html` (or a theme
  contains `x.svg`) with a script.
. A visitor or the admin opens `/media/xxxxxxxx-x.html`.
. The script runs on the site origin. It can `window.open` the OAuth sign-in
  page and read the token as it is typed; the CSP on that page does not stop
  a same-origin opener.

== Suggested fix

* Allow-list upload types, or serve everything that is not a raster image
  with `Content-Disposition: attachment`.
* Add `X-Content-Type-Options: nosniff` to `/media` and theme assets.
* Serve SVG with `Content-Security-Policy: sandbox` (or `default-src 'none'`),
  or drop `svg` from the theme asset allow-list.

== Resolution

`/media`, theme assets and scaled images go through `harden_file`, which
decides by file name (as `ServeDir` picks the content type), so a `304`
without a content type carries the same headers:

* Every file except PDFs gets `Content-Security-Policy: sandbox;
  default-src 'none'; img-src 'self' data:; style-src 'unsafe-inline';
  frame-ancestors 'self'`. Opened directly, an SVG renders but cannot run
  script on the site origin; as an `<img>`, font or stylesheet nothing
  changes. PDFs are not sandboxed because browsers then refuse to show
  them; their viewers run PDF scripts apart from the page's origin.
* Only images (SVG included), fonts, audio, video, CSS, plain text and
  PDFs are shown inline. Everything else, HTML, XML and scripts included,
  gets `Content-Disposition: attachment`. Uploads stay unrestricted, so
  existing files such as PDFs keep working.
* `nosniff` comes from the site-wide headers of
  link:039-public-site-security-headers.adoc[issue 39].
