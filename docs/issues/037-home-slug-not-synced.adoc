= 037: home_slug is not kept in step with page renames and deletes
:severity: Low
:area: Settings / site
:status: fixed
:found: 2026-10-24

[horizontal]
Severity:: Low
Area:: Settings / site
Status:: Fixed

== Summary

Renaming or deleting the home page, or setting `home_slug` to a page that
does not exist or is unpublished, leaves the setting dangling.

== Location

* `src/domain/settings.rs:119-125`
* `src/domain/pages.rs:222-270`
* `src/site.rs:184-186`
* `src/site.rs:251-274`

== Impact

`/` returns 404 instead of the page list, while the sitemap still lists
`/`.

== Suggested fix

* Update or clear `home_slug` on rename and delete.
* Validate the page when the setting is saved.
* Fall back to the page list when the home page is missing.

== Resolution

* Changing a page's slug moves `home_slug` along in the same transaction,
  and deleting the page clears it (`settings::move_home`).
* Saving `home_slug` checks that the page exists (400 otherwise). A draft
  is still accepted, as the admin UI offers drafts for it.
* `/` falls back to the list of published pages when the home page is not
  published, and the sitemap then dates `/` like that list.
