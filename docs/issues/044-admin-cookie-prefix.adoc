= 044: Admin cookies lack the __Host- prefix
:severity: Low
:area: wordmaker-admin
:status: fixed
:found: 2026-10-24

[horizontal]
Severity:: Low
Area:: wordmaker-admin
Status:: Fixed

== Summary

Cookies have no `__Host-` prefix, and `Secure` is set only when the public
URL is HTTPS. No HSTS is sent.

== Location

* `crates/wordmaker-admin/src/auth.rs:379-387`

== Impact

If the admin runs on a subdomain of the public site, script on the site
origin (e.g. via link:005-media-active-content-site-origin.adoc[issue 5])
can set `Domain=` cookies with the same names to force a logout or plant a
login cookie.

== Suggested fix

* Use the `__Host-` prefix on HTTPS and send HSTS.

== Resolution

When `WORDMAKER_ADMIN_PUBLIC_URL` is https, the session and login cookies
are named `+__Host-wordmaker_admin_session+` and
`+__Host-wordmaker_admin_login_<state>+` (always `Secure`, `Path=/`, no
`Domain`), so a sibling subdomain cannot set or shadow them; removals are
`Secure` too, as browsers require. Every response then also carries
`Strict-Transport-Security: max-age=31536000` (without
`includeSubDomains`, which would reach beyond this interface). Over plain
http, as on loopback, the names stay unprefixed and no HSTS is sent.
