[horizontal]

== Summary

`openPage` responses can arrive out of order.

== Location

* `crates/wordmaker-admin/assets/app.js:325-342`

== Impact

Click A then B; A's response arrives last, so the editor shows A while the
hash says B, and anything typed into B meanwhile is overwritten without a
prompt.

== Suggested fix

* Use a request counter, as `previewRequest` already does.

== Resolution

`openPage` numbers its requests like `previewRequest` does and drops an
answer when a later page has been asked for since. It checks again after
waiting for the editor to load, so an older call cannot put its body into
the editor after a newer page is shown.
