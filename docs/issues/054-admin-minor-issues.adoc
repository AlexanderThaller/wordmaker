== Summary

Small correctness gaps in the admin.

== Location

* `crates/wordmaker-admin/assets/app.js:193`
* `crates/wordmaker-admin/src/app.rs:143`
* `crates/wordmaker-admin/src/auth.rs:96`
* `crates/wordmaker-admin/src/auth.rs:500`

== Impact

* A malformed hash like `#/pages/%zz` makes `decodeURIComponent` throw, an
  unhandled rejection (self-inflicted only).
* `/config.json`, "Open site" and the dashboard links use the internal
  `WORDMAKER_BASE_URL`; they break and expose that address when it is
  internal.
* The fixed login cookie name means two sign-ins started in parallel tabs
  make the first fail.

== Suggested fix

* Catch decoding errors in the router.
* Add a separate public site URL setting for links.
* Key the login cookie by state, or tolerate parallel logins.

== Resolution

* The router catches `decodeURIComponent` errors; a mangled hash such as
  `#/pages/%zz` is treated as naming no page.
* New setting `WORDMAKER_ADMIN_SITE_URL` (`--site-url`): the site's public
  URL for `/config.json`'s `site_url`, which "Open site" and the
  dashboard's page links use. Without it they use `WORDMAKER_BASE_URL` as
  before. The "View" links come from the server's own page URLs and were
  already public.
* Parallel sign-ins: fixed with link:009-unbounded-tables-lockout.adoc[issue 9]; each sign-in now
  has its own login cookie, named after its `state`.
