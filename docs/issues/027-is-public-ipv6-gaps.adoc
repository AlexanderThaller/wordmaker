= 027: is_public misses IPv6 ranges that embed IPv4 or are not public

[horizontal]
Severity:: Low

== Summary

The address check used for client metadata fetches does not reject
IPv4-compatible `::a.b.c.d` (e.g. `::7f00:1`), 6to4 `2002::/16`, Teredo
`2001::/32`, site-local `fec0::/10` or discard `100::/64`.

== Location

* `src/oauth/client_metadata.rs:254-266`

== Impact

Depending on the network, a metadata URL resolving to such an address may
reach an internal host. Exploitability is uncertain.

== Suggested fix

* Reject these ranges and check embedded IPv4 addresses against the IPv4
  rules.

== Resolution

`is_public` now judges IPv4-compatible addresses (`::a.b.c.d`) by their
embedded IPv4 address, like IPv4-mapped ones, and refuses 6to4
(`2002::/16`), `2001::/23` (Teredo, benchmarking, ORCHID), site-local
`fec0::/10`, the discard prefix `100::/64` and the `3fff::/20`
documentation range, in addition to the ranges it already refused.
